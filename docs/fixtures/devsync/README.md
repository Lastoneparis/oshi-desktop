# Own-device sync golden vectors (`docs/fixtures/devsync/`)

These files are **the contract** for OSHI own-device sync ("direct strict",
[`docs/OSHI_DEVICE_SYNC_DIRECT.md`](../../OSHI_DEVICE_SYNC_DIRECT.md)). Every implementation (Kotlin
core shared by Android + Desktop, the future iOS/CryptoKit one) must reproduce every byte.

| File | What it pins |
|---|---|
| `keys.json` | PSK, DISC, device public keys → `deviceId`, hourly mDNS tags, 6-digit SAS codes |
| `noise_handshake.json` | `Noise_XXpsk0_25519_ChaChaPoly_SHA256` transcripts: relay + LAN prologues, every message, `h` after each message, split keys, SAS; negative cases (wrong PSK, spliced routing ids) |
| `noise_transport.json` | transport ciphertexts both directions, `Rekey()`, rekey-by-message-count and rekey-by-bytes sequences |
| `framing.json` | record header, `CONTINUED` flag, LAN frame, relay frames (both directions), `MEDIA_CHUNK` layout, size limits |
| `diff.json` | canonical JSON + `rev` per message, per-conversation `SUMMARY` digests, per-day `BUCKETS`, `IDS`, the expected `WANT` sets of two devices, a merged conflict |
| `merge.json` | message / contact / profile / read-state / group merge cases, `DEVICES` propagation + revocation |
| `relay_auth.json` | device-bound relay upgrade (`GET /v2/devsync`): binding string `B`, account + device signatures, headers for 3 devices (RFC 8032 seeds), the server's refusal table and close codes |

## Provenance and cross-check

- Generated by `gen_vectors.py` from **`devsync_ref.py`, an independent Python implementation**
  written from the Noise spec (rev 34) and the design doc, on pyca/cryptography (OpenSSL) primitives.
  `python3 gen_vectors.py --check` verifies the files on disk; `python3 gen_vectors.py` rewrites them.
- Before writing anything the generator checks its primitives against published answers
  (RFC 7748 §6.1 X25519, RFC 5869 A.1 HKDF, RFC 8439 §2.8.2 ChaCha20-Poly1305).
- The Kotlin implementation (`OSHI-Android/.../network/v2/devsync/`, BouncyCastle) shares **no code**
  with it and reproduces all of it: `DevSyncVectorCheck` (249 checks), run by
  `DevSyncVectorsTest` on Android and on Desktop.
- **No third-party Noise library was available offline** on the machine that produced these
  (no `noise`/`noiseprotocol` for Python, no Rust `snow`, no Go `flynn/noise`; the only Noise code
  found was WhatsApp's non-standard variant inside Baileys, which is not a valid oracle). The
  cross-check achieved is therefore **two independent implementations (Python/OpenSSL vs
  Kotlin/BouncyCastle) by the same author**. Anyone with network access should additionally run the
  handshake cases through `snow` (`Noise_XXpsk0_25519_ChaChaPoly_SHA256`, fixed ephemerals) — a
  shared misreading of the spec would pass both of ours.

## Decisions pinned here (also recorded in the design doc, Appendix C)

- **IK** = the raw 32-byte X25519 account private key as stored (not clamped).
- **PSK / DISC**: `HKDF-SHA256(ikm = IK, salt = "OSHI-DEVSYNC-v1", info = "noise-psk" | "mdns-tag", 32)`.
- **deviceId** = `SHA-256("OSHI-DEVSYNC-id" ‖ DK_pub)[0..16]`, written as 32 lowercase hex.
- **Prologue** = `"OSHI-DEVSYNC/1\n" ‖ transport ‖ "\n" ‖ min(idI, idR) ‖ max(idI, idR)` with the
  **raw 16-byte** ids in unsigned byte order (= lowercase-hex order). LAN: `"OSHI-DEVSYNC/1\nlan\n"` only.
  On the relay the **smaller deviceId initiates**.
- **Handshake payloads** are bare UTF-8 JSON, no record header: msg1 = `{"v":1}`, msg2 = responder
  HELLO, msg3 = initiator HELLO. After msg3 both sides check `deviceId == H(remote static)` and, on
  the relay, that it equals the routing id.
- **SAS** = `u32be(HKDF-SHA256(ikm = h_final, salt = empty, info = "OSHI-DEVSYNC-sas", L = 32)[0..4]) mod 10^6`,
  zero-padded to 6 digits. `h_final` = handshake hash after message 3. (Empty salt = 32 zero bytes.)
- **mDNS tag** = `hex(HMAC-SHA256(DISC, "t" ‖ u64be(floor(unix / 3600))))[0..16]`; accept current and previous hour.
- **Transport**: associated data is empty; nonce = 4 zero bytes ‖ u64 **little-endian** counter.
  **Rekey policy** per direction: after each message `count += 1`, `bytes += len(ciphertext)`; when
  `count ≥ 2^20` or `bytes ≥ 2^30` call `Rekey()` and reset both counters. `Rekey()` does **not** reset
  the nonce. Session max 1 h.
- **Relay upgrade auth** (`relay_auth.json`, 2026-09-23; server in `ServerPatches/devsync_device_auth/`,
  **not yet deployed**): `B = "OSHI-DEVSYNC-UPGRADE/1\n<identity>\n<deviceId>\n<dk>\n<dsk>\n<nonce>"`
  (UTF-8, no trailing newline; identity = normalised account key, dk/dsk = std padded base64 of the raw
  32-byte keys, nonce = 16 fresh random bytes as 32 lowercase hex). The account key signs
  `GET\n/v2/devsync\n<sha256hex(B)>\n<ts>` (B replaces the empty body); the device key `dsk` signs
  `OSHI-DEVICE/1\n<deviceId>\nGET\n/v2/devsync\n<sha256hex(B)>\n<ts>` with the same `ts`. Headers
  `x-oshi-device` (= `?device=`, must equal `H(dk)`), `x-oshi-device-dk`, `x-oshi-device-dsk`,
  `x-oshi-devsync-nonce`, `x-oshi-device-signature`, plus the usual `x-oshi-user` /
  `x-oshi-signing-pubkey` / `x-oshi-signature` / `x-oshi-timestamp`. The nonce is replay-cached per
  device for 60 s; an account-only upgrade gets 401 `device-auth-required`. Refusals and close codes
  (4000/4001/4003) are listed in the file.
- **Relay frame** (inside the WebSocket binary message): `[16-byte deviceId][u8 kind][Noise message]`,
  kind 1/2/3 = handshake message 1/2/3, 4 = transport. The kind byte lets a responder recognise a
  peer's fresh message 1 while a stale session exists. **LAN** frame: `u16be length ‖ Noise message`
  (no kind byte: one TCP connection is one session).
- **Record**: `u8 type | u8 flags | u32be seq | body` (≤ 65 519 bytes). `flags` bit0 = `CONTINUED`
  (body continues in the next record of the same type; reassembly cap 8 MiB). `seq` starts at 1 per
  direction and increases by 1 for every record **except `ACK` (0x02) and `BYE` (0x7F), which carry
  seq 0**, are outside the credit window and are never acknowledged. A record out of sequence is a
  protocol error.
- **Credit window**: at most 32 unacknowledged records or 2 MiB of record bytes; the receiver ACKs
  (`{"upTo": lastSeq}`) every 8 records or 250 ms.
- **`rev`** = `hex(SHA-256(utf8(canonicalJSON(revObject))))[0..16]` with
  `revObject = {deleted, edited: {text, at?} | null, reactions: {emoji: [sorted unique keys]}, read, status}`;
  `status` is `null` for `direction: "in"` (it is local state there); when `deleted`, `edited = null`
  and `reactions = {}`. Canonical JSON: keys sorted by UTF-8 bytes, no whitespace, escape only `"`, `\`
  and U+0000–U+001F (as `\u00xx`, lowercase hex); timestamps in canonical `yyyy-MM-dd'T'HH:mm:ss.SSS'Z'`.
- **digest** = `hex(SHA-256(join("\n", sort_utf8(asciiLower(id) ‖ ":" ‖ rev))))` (full 64 hex).
  Day buckets are UTC `YYYY-MM-DD`. Conversation ids in sync are canonical: `direct:<padded std b64>`,
  `group:<UPPERCASE UUID>`, `desktop:<nativeId>`.
- **Diff is pull-only and symmetric**: each side sends `SUMMARY` unsolicited and requests what *it*
  lacks: `BUCKETS_REQ{conv}` → `BUCKETS`, `IDS_REQ{conv, day}` → `IDS{conv, day, items:[[id, rev]]}`,
  `WANT{conv, ids ≤ 256}` → one or more `MESSAGES` (all but the last carry `"more": true`). `WANT`
  carries `conv` (additive to the design's `{ids}`).
- **Merge** (commutative, idempotent): see `merge.json` descriptions.
- **Groups (0x1C `GROUPS`, design §6 / §8.4)**: owner decision — members AND keys sync. Body
  `{groups:[{groupId, name, nameAt, avatar:{sha256,size,mime}|null, avatarAt, members:[userKey],
  admins:[userKey], epoch, epochAt, left, leftAt, joinedAt, keys:[{kind, version, key}], updatedAt}]}` plus optional
  descriptive extras (`description`, `type`, `creator`, `avatarEmoji`, `pinnedMessageId`, `pinnedBy`) that
  travel with the name. No epoch = 0. Rejoin rule (design C.16): `joinedAt` = max; a leave counts only if
  `leftAt >= joinedAt` (untimestamped: only while no join is known); `leftAt` = the latest leave that counts. Merge rules in `merge.json` (`groups[].canonical` is the canonical
  JSON of the merged group). Sent before `SUMMARY` so group messages land in groups that now exist.
- **DEVICES**: `{linked:[{deviceId, dk (hex of DK_pub), name, platform, approvedAt}], revoked:[ids]}`.
  An entry whose `dk` does not hash to its `deviceId` is refused; revocation is sticky and wins; self
  is never added.
- **Pairing**: a device may approve from ANY linked device (or either side when both are fresh). A
  device that has no linked device yet accepts the peer's `APPROVAL{approved:true}` as its own consent
  ("waiting for approval"); a device that already has linked devices must also approve locally. Data
  records are processed only once BOTH sides have approved.
- **Media**: `MEDIA_GET{sha256, offset, count}` → up to `count` `MEDIA_CHUNK`s of ≤ 60 KiB, `last=1`
  on the final one; the requester issues the next `MEDIA_GET` after `count` chunks. Partial files live
  in `<cache>/devsync/partial/<sha256>` and resume from their size; SHA-256 verified at the end (one
  retry on mismatch). Owner decision: media is allowed on cellular (default policy `always`).
